# Question ID source patch

Apply `question-id.patch` to pinned xyo-cpp revision `93c80a4bcc007284cdede0b927ec310145eaa0b5` together with the existing safe-runtime and lifetime patches before building the embedded browser library; reverse it in the same cleanup transaction. Export `_xyo_browser_answer_if_question` in both CJS and ESM linker export lists. The unpatched upstream CLI must not be linked to the modified browser.cpp.

IDs are nonzero runtime-local uint64 counters, assigned on enqueue (including queued entries), never reset by stop/green flag, and copied to a successfully loaded replacement Runtime. Exhaustion aborts instead of wrapping and reusing an ID. Snapshot IDs are canonical decimal strings to avoid JavaScript integer precision and wasm32 i64 ABI issues. A failed load preserves the old runtime and its counter. The new conditional answer returns -1 for stale IDs, without mutating the answer or queue; legacy `xyo_browser_answer` remains unconditional. IDs are local to a browser handle/module, not globally unique across destroyed handles or modules.

For an independent verification build, use a separate pinned checkout, apply the three patches, configure with `XYO_SAFE_WASM_DIR` pointing to this package's `src`, build libxyo, and link `browser.cpp` and `src/renderer_bridge.cpp` as in `scripts/build.sh` while adding `_xyo_browser_answer_if_question` to `EXPORTED_FUNCTIONS`. Then run `node scripts/test-question-id.cjs /absolute/path/to/xyo-browser.js` (the matching `.wasm` must be alongside it). If also applying browser-async-sound-integration.patch, guard the new ABI entry point with the same `BrowserCallGuard` as the other browser calls.
