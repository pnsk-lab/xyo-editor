# Headless shadow-motion candidate (design only)

The implemented experiment is narrower than the multi-statement proposal below: one isolated `motion_movesteps` with a numeric literal, no variable bindings, and private x/y/trigonometry slots. It is unavailable when a renderer or movement callback is attached. Multi-statement motion remains design only.

At execution time, immediately before speculation, require: an extant runtime; `runtime->renderer == nullptr`; `target->onTargetMoved == nullptr`; `!target->isStage`; `!target->dragging`; finite starting x/y and finite inputs and intermediates. The compiled region must be non-yielding and restricted to pure, validated numeric expressions, accepted variable operations and motion statements; no operation may observe the target or invoke host callbacks, and existing primitive identity, graph/cache/alias, bounds and variable-resolution checks remain mandatory. No other thread, host entry, reentrant callback or asynchronous action may mutate the target/runtime/variables from the guard through commit. This is a required execution model proof, not a consequence of the null callback checks alone. Keep direction fixed in a chunk unless every change and observer has separately been modeled.

Under those assumptions, each original `setXY` writes x/y and sets `runtime->refreshTargets = true` (`requestTargetsUpdate` is exactly that assignment). With no renderer and no movement callback, intermediate positions and repeated writes of `true` have no admitted observer. Compute every motion in sequence into shadow x/y, preserving x and y independently, normal cast rules and f64 evaluation order. If and only if the original chunk executes at least one motion, write the resulting pair using a single `setXY` after WASM succeeds, causing the same final x/y and refresh flag. A no-motion chunk must not call it. Using raw field assignments instead requires independently reproducing the flag and is less robust. Other target/variable commits must also be observationally equivalent; reject aliasing and any operation for which delayed variable writes alter input reads. Preserve signed zero, and bail before invocation/commit on nonfinite state, arguments or arithmetic intermediates; actual interpreter fallback must still process them normally. Do not merge operations algebraically or skip intermediate floating-point rounding.

For `movesteps`, the interpreter calculates `r = (M_PI * (90.0 - direction)) / 180.0`, then uses `v8math::cos(r)` and `v8math::sin(r)`. Compute these with identical native helpers and order, or prove bitwise equivalent WASM code; JS `Math` and generic platform trig are not a substitute. This proposed path remains useful for headless use only: attached-renderer fixtures fall back, and compiling a chunk does not by itself establish a runtime speedup.

All guard failures, CSP/compile failures, WASM traps and injected post-invoke failures must leave x/y, variables, refresh flag and all callbacks untouched before interpreter fallback. Stage speculative outputs in private memory; do not access live coordinates from generated code. No catch-and-retry after the final commit begins. Revalidation and reentrancy/lifetime rules, continuation/glow/frame/cache state and fair scheduling must match the existing safe compiler and interpreter, including a chunk starting after a completed say. Pending code must not survive a yield contrary to existing behavior.

Differential acceptance tests must assert safe execution actually occurs in the eligible headless case, compare exact double bits for every final coordinate and variable including negative zero, and compare `refreshTargets`, callbacks, thread stack/status/glow and continuation. Cover every opcode, multiple sequential mixed axes, zero-step motion, varied direction and V8 trig, nonfinite/overflow fallback, starting refresh flag true/false, stage/dragging fallback, renderer attached (including fencing disabled) and movement callback/pen fallback, changed guards after compilation, trap/CSP/failure injection, say-before-motion and same-step interacting threads. Include basic.sb3 with whichever renderer configuration it really uses and report compile **and execution** counts; a guard-induced fallback is not a compiled execution. Benchmark under the requested CPU affinity and parallelism only after correctness.
