# Headless single-axis motion: proposal and independent verification

Status: the isolated axis operation is implemented and exercised against the interpreter by the real-WASM `tests/axis_motion_test.cpp`. This proposal remains deliberately independent of the concurrent loop work.

## Scope and semantics

Accept only a single straight-line `motion_changexby`, `motion_setx`, `motion_changeyby` or `motion_sety` statement with its numeric shadow literal, after an eligible green-flag entry. Require a finite numeric literal using the same literal parsing and accepted shadow rules as the existing safe lowerer; reject dynamic reporters, malformed graphs, missing inputs and nonfinite literals. Keep all existing script, graph, cache, primitive-identity, alias and scheduler checks. Reject multiple motion statements or mixed motion/variable statements within the same compiled chunk. A script containing these can still execute a separate supported prefix or later chunk; loop bodies are not covered by this axis path. Do not alter loop lowering, scheduling, budget, fallback, or existing accepted program classification. Preserve existing `movesteps` behavior.

The canonical interpreter (`blocks/core.cpp`) performs exactly one call, with argument evaluation equivalent to:

| opcode | input | new x | new y |
|---|---|---|---|
| `motion_changexby` | `DX` | old x + literal | old y |
| `motion_setx` | `X` | literal | old y |
| `motion_changeyby` | `DY` | old x | old y + literal |
| `motion_sety` | `Y` | old x | literal |

Use IEEE f64 addition in interpreter operand order, not subtraction or an optimization such as eliding addition of zero. In particular `-0 + +0` is +0, whereas setting `-0` preserves its sign; the untouched coordinate must retain its exact bits. Do not treat equality as a no-op: `Target::setXY` requests a targets update even if the coordinates are unchanged. Do not fold several operations into one call: callbacks, pen strokes and per-call observable effects would be lost.

## Transaction and guards

Stage old coordinates and the resulting coordinates in private WASM slots. No target write or callback occurs before invocation succeeds and all validation is complete; on compilation rejection, trap, post-invocation failure or failed guard, fall back with original live state untouched. Commit using exactly one ordinary `Target::setXY(newX, newY)` after successful invocation, not direct coordinate stores; then mirror the existing safe completion/next block/glow protocol exactly. Preserve `runSafeFlag` graph revalidation, canonical primitive checks, cache/alias checks, binding restrictions and revalidation of the generated code against the current graph. The JS module handle map is not an isolation boundary against a hostile host with access to the runtime memory. Ensure cached execute initialization on fallback remains consistent with the existing path.

Conservatively reuse the motion guards: target and runtime exist, renderer absent (fencing/visual redraw), `onTargetMoved` absent (including pen movement hook), not stage, not dragging, finite x and y. Current movesteps additionally requires finite direction and trigonometric inputs; axis operations do not use direction, but initially retaining that guard is a safe, conservative choice. Check the computed result is finite *before commit*; finite operands may overflow. Nonfinite coordinates, literals or result must take the interpreter path, not be clamped or converted. A guard on result must not introduce writes before fallback. Do not infer that pen is inactive merely from renderer absence: its movement callback is independently observable. Check renderer and callback at execution time, not only compilation time; preserve their ordering by falling back to the interpreter.

Keep the axis operation explicitly classified separately from loops and from any prefix that could cross a yield/side effect. The existing one-motion constraint must be enforced for the entire accepted segment; guard failure must resume at the same original stack position, and an unsupported prefix/continuation must not be silently skipped. The actual implementation should be reviewed after the concurrent loop changes land, rather than copying assumptions about the current transient representation.

## Independent actual-WASM differential test contract

Create a separate C++ test and runner after the loop changes settle; do not edit the existing safe motion/loop test or their scripts. Construct each test graph from a fresh fixture, with only the selected axis motion statement, separately loaded into reference and optimized runtimes. Use the real Emscripten build, JS host bridge and dynamically instantiated WebAssembly; native execution or a mocked invoke is not evidence of WASM behavior. Run one identical sequencer step with safe JIT disabled on the reference and enabled on the optimized runtime, and compare bit patterns of both coordinates, status, complete stack, block/script glow, target refresh and redraw flags. Assert compilation and execution counters independently so matching interpreter fallbacks cannot masquerade as optimized coverage. Exercise all four opcodes with positive/negative/fractional values, each axis as untouched `+0` and `-0`, setting both zero signs, and changing both zero signs. Include finite overflow (e.g. max double plus max double) and nonfinite literal and initial coordinate cases; require fallback and interpreter-equivalent result, comparing NaNs by classification and all other values bitwise. Check finite unrelated direction and, if retaining the conservative guard, nonfinite direction fallback.

For every opcode, independently install a renderer that modifies fenced coordinates and records calls, a movement callback recording old coordinates, force and invocation count (including an actual pen-down hook where available), dragging and stage flags. Require execution counter unchanged and interpreter-equivalent side effects. Install guards after compilation but before the step to verify execution-time checking. Test absent runtime only if the fixture can model it without violating the interpreter's own preconditions. Force compile rejection, post-invoke failure and a genuine WASM trap separately, and check fallback has no double application, no duplicate callback and correct stack/glow. Mutate an opcode, literal, graph link or cached execute state between compilation and execution, and verify stale code cannot execute. Repeat a script after cache creation and verify the existing fallback/cache policy. Validate one completed statement and an unsupported trailing statement at the actual scheduler boundary; do not assume a safe prefix may consume it.

Add tests for multiple motion statements, a motion mixed with variables, and a motion nested in a loop: compare against the interpreter and verify that a single axis chunk never fuses multiple statements, even when a prefix or later chunk can run. Since the separate loop implementation may validly compile a loop through its own path, do **not** assert a global compilation/execution count of zero for all loop cases; use an explicit path-specific diagnostic or a dedicated isolated test configuration to distinguish the axis path, while separately running the existing loop regression suite unchanged. A positive axis test must assert the intended axis path actually executed. Run existing movesteps and loop suites unchanged alongside the new test. Tests must fail when axis compilation is absent. This section is a full acceptance plan; not every proposed case is necessarily covered by the current test.

Run builds/tests with `taskset -c 0-3,8-11` and `CMAKE_BUILD_PARALLEL_LEVEL=4` where that CPU set is available; report affinity failures rather than silently widening it. Use isolated build directories and the pinned checkout/patch procedure, after coordination with the owner of the concurrent changes. Do not present a native-only comparison as the real-WASM result.
