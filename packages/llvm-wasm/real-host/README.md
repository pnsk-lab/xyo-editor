# Isolated real xyo MAIN_MODULE experiment

This is not the product runtime or a general side-module loader. It builds the pinned xyo no-JIT Runtime/model/core/loader plus upstream `jit/rt.cpp`, excluding `src/wasm`. The no-JIT engine body is generated from upstream `nojit_stub.cpp`; its dummy C ABI helper definitions are explicitly excluded, not used to impersonate helpers. No LLVM archives or existing build files are changed. Use commit `93c80a4bcc007284cdede0b927ec310145eaa0b5` and the same Emscripten 6.0.12 as the compiler. Build:

```sh
source packages/xyo-cpp-wasm/.work/emsdk/emsdk_env.sh
export PATH="$PWD/packages/xyo-cpp-wasm/.work/tools/bin:$PATH"
taskset -c 0-3,8-11 env CMAKE_BUILD_PARALLEL_LEVEL=4 emcmake cmake -G Ninja -S packages/llvm-wasm/real-host -B packages/llvm-wasm/real-host/build -DXYO_SOURCE="$PWD/packages/xyo-cpp-wasm/.work/xyo-cpp"
taskset -c 0-3,8-11 env CMAKE_BUILD_PARALLEL_LEVEL=4 cmake --build packages/llvm-wasm/real-host/build
```

`rh_create` loads real SB3 bytes and accepts exactly one script, which must be a green flag. Check `rh_error` before all operations. It makes an actual Thread and JitCtx with the loaded target and runtime. The loader must independently verify the entire accepted script and compiler output: this API itself does **not** authorize arbitrary generated code. The structural admission mirrors the compiler's straight-line set/change chain subset (up to 8 blocks, numeric shadows only), but is not a byte-for-byte fixture identity check. `rh_layout` exposes pointer size, JitCtx size, varSlotData offset, Variable value offset, Value size, SStr size, and thread/target/runtime offsets. Compare against the exact producing compiler and IR, not just a version string. This is not a complete ABI fingerprint. The wasm32 `ctxPtr` stride fix is applied in the metadata compiler's disposable build (verified by `llvm_ctx_stride_test.py`); general `ctxPtr` code paths remain unverified for execution. No general ABI compatibility is claimed.

`rh_bind_slot(host, slotAddress, kind, key, length)` binds actual writable module global storage, not a fake variable object. Upstream kind 0/1 holds stable NUL-terminated bytes, kind 2 resolves `targetIndex\\1blockId` (missing separator defaults to target 0), and kind 3 creates a GC-managed SStr from raw little-endian UTF-16. Other kinds fail. The root provider is registered on host construction, before allocation; each address is added before its literal is created. The slot storage must remain mapped until `rh_destroy`, which clears slots and removes the root. Destroy the host (and its Thread/cache) before unloading the side module or its slot memory. Never unbind, modify or unload slots while running; failed creation/binding must not be executed. `rh_variable`, `rh_var_slot`, and `rh_variable_bits` inspect actual loaded variables, cached pointers, and NaN-boxed values. `rh_collect` exercises the real GC. `rh_dlsym` exposes the native Emscripten loader without admission checks. Handles should be opened with `rh_dlopen_for(host, path)`, which records the owning host: `rh_dlclose` refuses to unload while that host is alive, and a destroyed owner releases its registrations so recycled handle values can never resolve to it (a sticky closed-handle set was tried and removed after stress testing proved handle values are recycled). Slot ownership is enforced: `rh_expect_slots` declares the verified count first, `rh_bind_slot` refuses addresses owned by another live host and binds beyond the declared count, and `rh_invoke` runs only sealed hosts (exactly the declared binds). Reentrancy needs no guard for the current subset and has none: every `rh_*` entry point is callable only from JS, the linked side modules import exactly the pinned helper set (`xyo_varslot_init`, plus `xyo_to_num` only where the fixture uses it) plus GOT slots — none of which call back into host code — and single-threaded Wasm has no preemption points (the no-yield gate admits no yielding constructs). Stale-handle use outside the ownership/unload checks remains caller-managed. If any future helper that can call back, or any yielding construct, is admitted, a reentrancy guard becomes mandatory and the per-fixture exact import tests are the tripwire. A 50-cycle sequential lifecycle stress test (`side-stress.cjs`, wired into `run.sh`) exercises create/bind/invoke/collect/destroy/dlclose churn with per-iteration value asserts. Actual metadata validation, hash checks, slot identities and script admission remain the caller's responsibilities. In particular MAIN_MODULE=2 may allow dlopen to succeed for unresolved functions until call time, so preflight the exact import names, kinds and availability before any execution; do not rely on RTLD_NOW. The separate metadata prototype exposes AotEmit metadata; the older compiler wrapper does not. Inventing slot bindings is not a replacement. UTF-16 byte order assumes wasm little-endian. This experiment is not safe for untrusted SB3.
