# Single-fixture integration result and reproduction

The isolated test passed in Node and in a headless Brave Worker: the same SB3 bytes go to the metadata compiler and real Runtime. Native xyo codegen emits the reviewed IR; Wasm LLVM llc and Wasm LLD produce a side module; Emscripten dlopen/dlsym use the MAIN_MODULE memory and table; real `xyo_varslot_init` resolves ID `v` to the loaded `Variable`; `ScriptFn(JitCtx*)` stores the real GC-managed SStr `42`. The variable slot points to that real variable, its Value bits point to the real SStr, and its UTF-16 contents and bits survive explicit GC before/after execution. The host and root are destroyed before `dlclose`. ABI descriptor matched: partial FNV `2749f0107810386f` (now covering NaN-boxing tags and the recorded helper signature, so same-layout/different-tag rebuilds mismatch); that FNV is not authentication or proof of general ABI compatibility. No scheduler was exercised.

Node preflights the exact decompressed single `project.json` SHA-256 `474887048515a6670d9048e9b6ef5552f3e4c086bb89a1dbe19129af4e434836`, exact slot keys and the exact IR SHA-256 `8e67d9f394e6382994dc6c244cc254baa559c49e1711346fdef32f6e5e764f75`, exact side SHA-256 `baa20b3672d88e894d568bc2edc12fa566ac65310d29e9dfcdabc4227b228e09`, exact imports/exports/dylink, actual compiler metadata and host descriptor. It rejects changed SB3 literal and variable ID, altered slot keys, a modified unknown helper import, modified side hash and mismatched ABI descriptor before invocation. Separate smoke checks reject wait, two hats, missing side, unsupported kind and odd UTF-16. Host admission checks additionally feed NUL-id, NUL-name, and a 2 GiB-central-size ZIP bomb straight to `rh_create`, asserting clean `rh_context == 0` rejections with `VARIABLE id` / `VARIABLE name` / `zip preflight` errors and no large allocation. These are narrow checks, not a security proof. The browser Worker generates IR/metadata from the same fixture, runs browser Wasm llc+LLD and compares every byte against the reviewed Node side except the non-semantic Wasm `name` custom section; it checks the IR and reference hashes and compares descriptors before invocation. The filename appears in LLD's `name` custom section, hence Node must output `parent.wasm` to reproduce the reviewed SHA. LLD warns that `--shared` is not yet stable.

Build the separate metadata compiler and browser llc/lld proof artifacts first. Then from the repository root:

```sh
taskset -c 0-3,8-11 env CMAKE_BUILD_PARALLEL_LEVEL=4 BROWSER=/path/to/brave bash packages/llvm-wasm/real-host/run.sh
```

The runner builds the host, generates its own fixtures and browser pipeline bundles inside `real-host/build`, copies the compiler JS/Wasm pair there, prints their hashes and generates its reviewed reference with the Node test before the browser test. It reads the separately built metadata compiler and browser llc/lld artifacts; it does not rebuild or write the existing LLVM build tree. The browser compares the ZIP's SHA to the Node-validated bytes. Browser tests execute in an ephemeral loopback server and close it afterwards.

## Critical scope and ownership limits

This is deliberately **not** product code, a general SB3 compiler, a general Wasm security boundary, or a complete ABI fingerprint. The wasm32 `ctxPtr` stride fix is applied in the metadata compiler's disposable build (verified by `llvm_ctx_stride_test.py` plus byte-identical fixture IR); this exact IR does not exercise `ctxPtr`, and general `ctxPtr` paths remain unverified for execution. Both the metadata compiler and the host now run the same strict fail-closed ZIP preflight (stored/deflate only, 4096 entries max, 16 MiB per entry, 64 MiB total, `project.json` required) before `loadSb3File`, so the patched-2 GiB central-directory size is rejected without allocating; both require exactly one script overall with a single green flag; and both reject variable ids/names containing NUL (plus a post-emit VarId slot-key check in the compiler) since they would truncate as C strings. These admission ranges are now aligned, but only for this narrow subset. The host APIs remain trusted test-only primitives, now with enforced binding discipline: `rh_expect_slots` declares the verified slot count up front, `rh_bind_slot` refuses addresses owned by another live host and any bind beyond the declared count, the host seals only after exactly that many binds, and `rh_invoke` refuses unsealed or foreign hosts. Verified: unsealed invoke leaves the variable untouched, a second host is refused the live host's slot address, rebinding after the owner's destruction succeeds, and over-binding or double declaration is rejected. Still caller-managed and unenforced: teardown while code is in flight (untestable: no callback path exists for it to happen through), in-flight execution guards, or general slot-range validation. Nested `rh_invoke` reentrancy is impossible by construction for the admitted subset (JS-only entry points, callback-free pinned imports, no preemption); admitting callbacks or yields would reopen it. Handle values are recycled by the loader across generations, so unload tracking is strictly owner-based; a stale per-value closed set was removed after lifecycle stress proved it poisons recycled values. A 50-iteration sequential lifecycle stress test (create/bind/invoke/collect/destroy/dlclose with per-iteration value and GC-stability asserts) passes. A future product API must additionally bind module handle, target/project generation and validated address ranges one-to-one, quiesce execution before teardown, and provide rollback. Caller checks here are valid only for the exact fixed fixture. The root design itself requires slot storage to stay mapped until host destruction; do not use it with untrusted callers. Product integration, arbitrary slot kinds, broad GC stress, clones, yield, scheduler semantics and general projects remain unverified. Import name/kind allowlisting alone does not authenticate code, start functions, constructors or ABI, and dlopen can run constructors: this test relies on the reviewed fixed side bytes before dlopen, not on that allowlist as a sandbox.
